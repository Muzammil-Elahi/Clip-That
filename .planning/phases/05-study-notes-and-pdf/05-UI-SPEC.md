## Layout Specification

### Notes Tab Content — Three States

The Notes tab (`<TabsContent value="notes">`) in the existing `status-view.tsx` at line 272 replaces:

```
<p className="text-base text-muted-foreground">
  Study notes will appear here in a future update.
</p>
```

With the following conditional rendering based on `studyNotes` state:

**State A — Loading (studyNotes is null and job status is DONE but notes not yet arrived via Realtime):**

```
<div className="flex flex-col gap-4">
  <p className="text-base text-muted-foreground">
    Generating your study notes...
  </p>
</div>
```

A plain text placeholder is used (Claude's discretion per D-06); no spinner component to add. This matches the lightweight pattern used in the Video tab while video is processing ("Working on it...").

**State B — Notes available (studyNotes is a non-empty string):**

```
<div className="flex flex-col gap-4">
  <div className="prose prose-neutral max-w-none">
    <ReactMarkdown>{studyNotes}</ReactMarkdown>
  </div>
  <PDFDownloadLink
    document={<StudyNotesPDFDocument topic={topic} studyNotes={studyNotes} youtubeUrl={youtubeUrl} />}
    fileName={`study-notes-${topic}.pdf`}
  >
    {({ loading }) => (
      <Button variant="default" size="sm" disabled={loading} className="w-fit">
        {loading ? 'Preparing PDF...' : 'Download PDF'}
      </Button>
    )}
  </PDFDownloadLink>
</div>
```

- Prose container: `prose prose-neutral max-w-none` — neutral color palette matches Geist/neutral theme; `max-w-none` prevents prose from constraining width inside the card.
- PDF button: right below the notes content, left-aligned (`w-fit`), not full-width. Lucide `Download` icon (16px) placed to the left of the label text with `gap-2` (8px).
- PDF button label during PDF generation: `Preparing PDF...` (disabled state).
- PDF button label when ready: `Download PDF`.

**State C — Soft-fail (studyNotes is null and job status is DONE, notes never arrived):**

Detected when job status is DONE and `studyNotes` remains null after the Realtime/polling cycle has settled. Because both Realtime and polling can deliver null explicitly (soft-fail path), the component distinguishes loading from soft-fail by tracking whether the job transitioned to DONE — once DONE is confirmed and `studyNotes` is still null, show the soft-fail message.

```
<div className="flex flex-col gap-4">
  <p className="text-base text-muted-foreground">
    Notes could not be generated. Your video and transcript are still available.
  </p>
</div>
```

This copy is locked from D-09 in `05-CONTEXT.md`.

### PDF Document Layout (`StudyNotesPDFDocument`)

Implemented as a `@react-pdf/renderer` `Document` + `Page` component tree. Layout (Claude's discretion per D-08):

```
Page (A4, padding: 48pt all sides)
  ├── Section: Header
  │   └── Text "Study Notes: [topic]"  — 20pt, bold, color #1a1a1a
  ├── Section: Divider line  — 1pt height, color #e5e5e5, margin-bottom 16pt
  ├── Section: Notes body
  │   └── Text (plain string — Markdown stripped or rendered as plain text)
  │       16pt, normal weight, line-height 1.6, color #1a1a1a
  └── Section: Footer
      └── Text "Source: [youtubeUrl]"  — 10pt, normal, color #6b7280
```

Font: Helvetica (built-in `@react-pdf/renderer` font — no external font fetch required). Neutral, readable. Do not use Geist inside the PDF; it is not a built-in PDF font.

Markdown-to-plain-text: Strip Markdown syntax characters (`##`, `**`, `-`, etc.) before passing to the PDF `Text` node. The PDF body is plain text only — `@react-pdf/renderer` does not parse Markdown. A lightweight strip regex is sufficient; no additional library needed.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Download PDF` |
| Notes tab label | `Notes` (unchanged from Phase 3) |
| Notes tab loading state | `Generating your study notes...` |
| Notes tab soft-fail | `Notes could not be generated. Your video and transcript are still available.` |
| PDF button loading state | `Preparing PDF...` |
| PDF download filename | `study-notes-[topic].pdf` (topic value lowercased, spaces replaced with hyphens) |
| PDF header | `Study Notes: [topic]` |
| PDF footer | `Source: [youtubeUrl]` |
| Empty state heading | Not applicable — Notes tab has no empty state; notes are either loading, available, or soft-failed |
| Error state (FAILED job) | Unchanged from Phase 1: existing `errorMessage` displayed in `AlertDescription`. Heading: `Something went wrong`. Button: `Try again` |
| Destructive confirmation | Not applicable — no destructive actions in this phase |

Copy rules:
- Topic interpolation uses the job `topic` field value verbatim (same as Transcript tab empty-state pattern).
- `Download PDF` is imperative verb + noun — matches the Primary CTA pattern from prior phases.
- Soft-fail message is neutral and informative: explains the failure without alarming language, and immediately redirects the user to what is still working.
- All copy uses sentence case. No exclamation marks. No emoji.

Source: D-05, D-06, D-07, D-08, D-09 from `05-CONTEXT.md`. PDF filename and header formats are Claude's discretion per D-08.

## State Matrix

| State | Notes Tab Content | PDF Button |
|-------|------------------|------------|
| PENDING / PROCESSING | Notes tab not visible (no tab container during processing) | Not visible |
| DONE — studyNotes loading (null, Realtime not yet delivered) | `Generating your study notes...` (text placeholder) | Not visible |
| DONE — studyNotes available (non-empty string) | `react-markdown` rendered prose | `Download PDF` button visible |
| DONE — studyNotes soft-fail (null after Realtime settled) | `Notes could not be generated. Your video and transcript are still available.` | Not visible |
| FAILED | Notes tab not visible (no tab container on failure) | Not visible |

Notes:
- Video tab and Transcript tab states are unchanged from Phase 4. This matrix covers Notes tab only.
- The loading vs. soft-fail distinction: track a `notesSettled` boolean in component state, set to `true` when the Realtime/polling cycle delivers a DONE update (whether `studyNotes` is null or not). If `notesSettled && studyNotes === null`, show soft-fail. If `!notesSettled && studyNotes === null && isDone`, show loading.

## Accessibility

- Notes tab is an existing `TabsContent` element — Radix UI tab panel ARIA (`role="tabpanel"`) is already provided. No new ARIA roles needed.
- `react-markdown` renders semantic HTML (`<h2>`, `<ul>`, `<li>`, `<p>`, etc.) inside the prose container — accessible heading hierarchy is preserved from Gemini's Markdown output.
- PDF download button: uses shadcn `Button` which renders as a native `<button>`. Disabled state (`disabled={loading}`) is natively communicated to assistive technology.
- Loading placeholder text is plain `<p>` — no `aria-live` needed; the Notes tab is only seen after the job is DONE, and the user must actively switch to the Notes tab to see it (no auto-focus transition).
- Soft-fail message is plain `<p>` — no alert role needed; it is informational, not an error requiring immediate attention (video and transcript remain accessible).
- Minimum tab trigger touch target: 44px height — established in Phase 3 UI-SPEC; unchanged.

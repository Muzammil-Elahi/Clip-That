<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase Realtime → browser state | studyNotes string (AI-generated) arrives via WebSocket and is set in React state |
| React state → DOM via react-markdown | studyNotes Markdown rendered as HTML in the browser |
| React state → PDFDownloadLink → browser download | studyNotes used to generate a client-side binary PDF |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05 | XSS | react-markdown rendering studyNotes | mitigate | react-markdown is safe-by-default — renders semantic HTML elements (h2, ul, li, p) only; does not use dangerouslySetInnerHTML. No custom renderer that re-enables HTML. This is the ASVS L1 V5 (output encoding) control. |
| T-05-06 | XSS | PDF download | accept | PDFDownloadLink generates a local Blob download — the content is not injected into the DOM. No XSS vector. The PDF is never served from a URL that could be framed or opened in a tab without user interaction. |
| T-05-07 | Information Disclosure | PDFDownloadLink ssr: false | accept | dynamic() with ssr: false prevents server-side execution of browser-only PDF code; the component is never exposed as a server endpoint. |
| T-05-08 | Tampering | studyNotes from Realtime payload | accept | Realtime payload is keyed by job ID filtered to userId=eq.<uid> (established in Phase 1/3); studyNotes value originates from worker Gemini call, not from user input. The value is rendered as Markdown text, not executed. |
| T-05-SC | Tampering | npm install react-markdown / @react-pdf/renderer / @tailwindcss/typography | mitigate | Package Legitimacy Audit in 05-RESEARCH.md: all three packages verified as OK or approved-SUS (official publishers, high download counts). No blocking checkpoint required per audit. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase Realtime → Browser | videoUrl arrives in the Realtime payload; must only reach the owning user's channel |
| Browser → HTML5 video element | videoUrl is set as src on <video>; must be a legitimate Supabase-signed URL, not a user-controlled string |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07 | Information Disclosure | videoUrl in Realtime payload | mitigate | Realtime channel is filtered to `id=eq.${initialJobId}` per existing subscription; only the job owner receives the payload; RLS enforced on Job table |
| T-04-08 | Tampering | videoUrl rendered as <video src> | mitigate | videoUrl comes from the database via Realtime (server-controlled); it is not a user-supplied string; no XSS risk from src attribute; Content Security Policy (already in place from Phase 1) restricts media-src |
| T-04-09 | Information Disclosure | topic rendered in "No clips found for {topic}" | mitigate | topic is a JSX text node child — never uses dangerouslySetInnerHTML; same pattern as existing transcript entry rendering (T-03-06) |
| T-04-SC | Tampering | No new npm packages in frontend | accept | No new packages installed in Next.js app for this plan; HTML5 <video> is a native browser API |
</threat_model>

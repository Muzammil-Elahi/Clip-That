## Phase Goal

**As a** student studying a YouTube lecture, **I want to** see a checkbox on the submission form and have semantically matched segments labeled in my transcript view, **so that** I can opt into richer search and understand which clips were found by meaning rather than exact words.

<objective>
This plan delivers the complete frontend vertical slice for optional semantic matching. The user sees a "Also find related references" checkbox on the submission form, the Server Action validates and persists the choice, and the Transcript tab labels semantic-matched segments with a "(semantic)" badge so the student knows which clips were found by conceptual similarity rather than exact wording.

Purpose: Close the user-facing loop started by Plan 01 — the backend already computes and stores semantic matches with matchType and confidence; this plan makes the toggle visible to the user and makes the distinction visible in the transcript.

Output: shadcn Checkbox component, submission form with toggle, schema + action update, frontend type mirror, Transcript tab label for semantic segments.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form → Server Action | User-supplied checkbox value (semanticEnabled='on' or absent) crosses trust boundary; must be coerced and validated |
| Server Action → Database | Validated boolean written via Prisma; DB default is authoritative |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-F01 | Tampering | Browser manipulates semanticEnabled form field to arbitrary value | mitigate | `z.coerce.boolean().optional().default(false)` in submitJobSchema coerces any value — 'on' → true, anything else → false; only two outcomes possible regardless of client input |
| T-06-F02 | Tampering | Client sends semanticEnabled=true when checkbox not shown | accept | Server Action processes the field via Zod coercion; semanticEnabled=true simply enables semantic path in the worker — no security boundary crossed; the feature is an opt-in convenience, not access control |
| T-06-F03 | Information Disclosure | confidence score display in UI reveals internal model calibration | accept | v1 shows only "(semantic)" text label — no numeric score exposed in the UI; raw score stored in clipPlan DB field for future use only; students cannot infer model internals from the label |
| T-06-SC | Tampering | npm package installation (shadcn checkbox) | mitigate | shadcn CLI generates local source code from templates — it does not add an npm runtime dependency; the generated checkbox.tsx is first-party code; no new entry in package.json runtime dependencies |
</threat_model>

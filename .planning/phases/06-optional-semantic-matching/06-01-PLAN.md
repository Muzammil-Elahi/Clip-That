## Phase Goal

**As a** student studying a YouTube lecture, **I want to** optionally get semantically related clip segments included in my study artifacts, **so that** I can find relevant content even when I used different words than the lecture.

<objective>
This plan delivers the complete backend vertical slice for optional semantic matching. When the Prisma migration adds `semanticEnabled` to the Job model, the new `semanticMatcher.ts` module runs embedding + cosine scoring against Gemini `gemini-embedding-001`, and `worker/src/index.ts` merges semantic matches into `clipPlan` — a student who opts in on the form gets semantically enriched clip plans stored in the database, ready for the downstream video pipeline and transcript view.

Purpose: Deliver the semantic retrieval engine end-to-end — schema → types → module → worker integration — so the option is functional before the frontend toggle is visible.

Output: Prisma migration, ClipMatch type extensions (worker + will be mirrored by Plan 02), semanticMatcher.ts module, full unit test suite, reference dataset fixture, and worker index.ts integration wired to job.semanticEnabled.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Form → Server Action | User-supplied `semanticEnabled` checkbox value crosses from untrusted client to Server Action |
| Server Action → Database | Validated `semanticEnabled` boolean written to Job row; Prisma `@default(false)` is authoritative |
| Worker → Gemini API | `GEMINI_API_KEY` is the credential crossing to Google's embedding service; must stay worker-only |
| Gemini API → Worker | Embedding response `response.embeddings[i].values` — structure guard required before use |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | Form semanticEnabled checkbox → Server Action | mitigate | `z.coerce.boolean().optional().default(false)` in Zod schema coerces any non-'on' value to false; `@default(false)` on Prisma column is the authoritative DB default; Server Action is the only write path (RLS on Job table) |
| T-06-02 | Tampering | topic string embedded via Gemini embedContent | accept | Embedding models are not generative — injected instructions in the topic string have no effect on cosine similarity computation; the output is a numeric vector, not a completion |
| T-06-03 | Information Disclosure | GEMINI_API_KEY in worker environment | mitigate | Key is only in `worker/.env.local` and Railway worker environment variables; never in `NEXT_PUBLIC_` prefix; never returned to client; existing pattern from Phase 5 unchanged |
| T-06-04 | Elevation of Privilege | Cost amplification via semanticEnabled=true on large transcripts | mitigate | `MAX_SEMANTIC_MATCHES = 10` caps output count; `EMBED_CHUNK_SIZE = 20` with sequential for-loop prevents burst-429 and bounds total API calls; Gemini free tier limits bound total cost at v1 volume |
| T-06-05 | Denial of Service | Gemini API 429 / timeout causes job failure | mitigate | `findSemanticMatches()` wrapped in try/catch in index.ts; any thrown error results in `semanticMatches = []` and job continues with exactMatches only; one retry on 429 before soft-fail |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No new npm packages installed in this phase — all dependencies (@google/genai, vitest, zod, prisma) are already installed and audited in prior phases (Phase Legitimacy Audit in 06-RESEARCH.md confirms) |
</threat_model>

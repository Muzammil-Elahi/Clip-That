  <action>
    Create worker/src/matcher.ts as a pure utility module (no side effects, no I/O). Module-level JSDoc describes it as "Transcript normalization and exact topic matching utilities for Phase 2."
    No imports from @/ aliases. Import types using: import type { TranscriptSegment, ClipMatch } from './types.js' (note .js extension — ESM with "type": "module").

    Export function normalize(text: string): string
    - Lowercase the entire string
    - Replace any character that is not a word character (\w) or whitespace (\s) with empty string
    - Replace one or more whitespace characters with a single space
    - Trim leading/trailing whitespace
    Per D-06: strip punctuation, normalize whitespace, lowercase.

    Export function findMatches(segments: TranscriptSegment[], topic: string): ClipMatch[]
    Algorithm:
    1. normalizedTopic = normalize(topic)
    2. Iterate segments with index i:
       a. Single-segment check (D-07): normalize(segments[i].text) includes normalizedTopic → push ClipMatch:
          - startMs: Math.round(segments[i].offset * 1000)
          - endMs: Math.round((segments[i].offset + segments[i].duration) * 1000)
          - text: segments[i].text
          - segmentIndices: [i]
          - continue (do not also check cross-boundary for same segment)
       b. Cross-boundary check (D-08): if i+1 < segments.length, normalize(segments[i].text + ' ' + segments[i+1].text) includes normalizedTopic → push ClipMatch:
          - startMs: Math.round(segments[i].offset * 1000)
          - endMs: Math.round((segments[i+1].offset + segments[i+1].duration) * 1000)
          - text: segments[i].text + ' ' + segments[i+1].text
          - segmentIndices: [i, i+1]
          - increment i by 1 (i++) to skip the consumed next segment
    3. Return matches array (empty array if no matches — per key_research_findings: no-match → DONE with empty clipPlan, NOT FAILED)
    CRITICAL: Use seg.offset (not seg.start) — seg.start does not exist on TranscriptSegment; it would silently produce NaN.

    Also export function buildClipPlan (convenience alias for findMatches — same signature) so index.ts can call buildClipPlan(segments, topic) per the established naming in the RESEARCH patterns.

    Create worker/src/__tests__/matcher.test.ts with import from '../matcher.js' (.js extension required by ESM). Write describe blocks for:

    - buildClipPlan: aliases findMatches (same result for same input)
    Tests use vitest describe/it/expect pattern matching src/__tests__/youtube.test.ts structure.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | job.topic passed to normalize/findMatches | accept | normalize() lowercases and strips non-word characters; findMatches uses String.prototype.includes() (not eval or regex); no injection vector |
| T-02-07 | Denial of Service | Very long transcript (>10,000 segments) causes slow matching | accept | findMatches is O(n) where n = segment count; a 90-min video at 1 segment/3s yields ~1,800 segments; no practical DoS risk for Phase 2 MVP |
| T-02-08 | Information Disclosure | clipPlan JSON stored in Supabase contains user topic | accept | The topic was already stored in job.topic in Phase 1; clipPlan adds no new sensitive data; RLS ensures only the owning user's session reads their own job rows via Next.js |
| T-02-SC | Tampering | No new npm installs in this plan | accept | Plan 02-02 adds no new packages to worker/; all dependencies installed in Plan 02-01; slopcheck N/A |
</threat_model>

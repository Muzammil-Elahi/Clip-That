## Phase Goal

**As a** student, **I want to** see a stitched transcript of matching video moments with source timestamps, **so that** I can review exactly what was said about my topic without watching the full video.

<objective>
Build the worker-side vertical slice for context-aware clip planning and stitched transcript generation. This plan takes the existing `clipPlan` (ClipMatch[]) produced by Phase 2 and runs it through context expansion, overlap merging, and stitched transcript assembly — then persists `stitchedTranscript` on the Job row alongside `clipPlan`. After this plan the worker writes real context-expanded, timestamp-annotated transcript data to the database; the frontend display comes in Plan 03-02.

Purpose: Satisfy CLP-02 (30s context windows), CLP-03 (overlap merging), CLP-04 (source timestamp preservation), and STR-01 (stitched transcript generation). This is the backend half of the Phase 3 user story.

Output: Two new pure-function worker modules (`contextExpander.ts`, `stitchedTranscript.ts`), an extended `types.ts`, a Prisma schema migration, an updated `worker/src/index.ts`, and full unit test coverage for both new modules.
</objective>

  <behavior>
    contextExpander.ts — expandContextWindows:
    - Empty matches → returns []
    - Single match at segment index 5 in a 20-segment array, segments 0–4 cumulate >= 30s left, segments 6–10 cumulate >= 30s right → result startIdx < 5, endIdx > 5
    - Match at segment index 0 (video start) → leftIdx stays 0, startMs = Math.round(segments[0].offset * 1000), no error
    - Match at segment index segments.length-1 (video end) → rightIdx stays at segments.length-1, no error
    - startMs and endMs are derived from `offset` (not NaN); endMs = Math.round((segments[rightIdx].offset + segments[rightIdx].duration) * 1000)

    contextExpander.ts — mergeOverlappingWindows:
    - Empty input → []
    - Two non-overlapping windows (window A endMs < window B startMs) → returns both unchanged
    - Two overlapping windows (window A endMs >= window B startMs) → merged into one with startMs=A.startMs, endMs=max(A.endMs, B.endMs), endIdx=max(A.endIdx, B.endIdx)
    - Two adjacent windows (window A endMs === window B startMs) → merged (curr.startMs <= last.endMs condition is satisfied)

    stitchedTranscript.ts — buildStitchedTranscript:
    - Empty mergedWindows → []
    - Single window covering indices 2..4 → 3 entries in order; entry 0 has sourceStartMs = Math.round(segments[2].offset * 1000)
    - Two non-adjacent windows → entries from both windows in sequence, no gap marker between them (D-05)
    - sourceStartMs and sourceEndMs are not NaN (derived from offset, not start)
  </behavior>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | Worker writes stitchedTranscript to Job row for any job it picks up | accept | Worker only processes jobs it fetched from DB with status=PENDING; no user-supplied field controls which job is processed |
| T-03-02 | Tampering | expandContextWindows / mergeOverlappingWindows pure functions | accept | Pure functions with no I/O; inputs are already-stored transcript segments validated at fetch time |
| T-03-03 | Denial of Service | buildStitchedTranscript on a very long transcript producing a large JSONB blob | accept | MVP targets typical lecture clips; Supabase 1MB Realtime payload limit already documented in RESEARCH.md; no mitigation needed at Phase 3 |
| T-03-04 | Information Disclosure | stitchedTranscript readable by wrong user via Supabase Realtime | mitigate | Realtime channel filtered to `id=eq.${initialJobId}` (existing pattern from Phase 1); RLS on Job table enforced in Supabase by userId policy |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new npm packages in this plan; only npx shadcn add tabs in plan 03-02 |
</threat_model>

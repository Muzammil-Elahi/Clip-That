## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label / Caption | 14px | 400 (regular) | 1.4 |
| Heading | 24px | 600 (semibold) | 1.2 |
| Timestamp | 14px | 600 (semibold) | 1.4 |

Notes:
- Body (16px / 400) applies to transcript entry text and coming-soon messages.
- Label / Caption (14px / 400) applies to muted secondary text (`text-muted-foreground`).
- Heading (24px / 600) applies to the "Done!" h1 and tab panel section labels. Source: existing `status-view.tsx` uses `text-2xl font-semibold` for the h1.
- Timestamp (14px / 600) applies to the `[M:SS]` timestamp prefix on each transcript entry — semibold to visually distinguish it from the body text that follows.
- Only two weights used: 400 and 600.

Source: `status-view.tsx` class `text-2xl font-semibold leading-tight` for headings; `text-base text-muted-foreground` for body copy.

## Layout Specification

### Result Page — Done State Structure

Replace the existing Done-state placeholder `<p>Your results are ready.</p>` in `status-view.tsx` with:

```
<Card max-w-2xl w-full>
  <CardContent p-6 gap-6>
    <h1 "Done!" text-2xl font-semibold>    ← existing heading (unchanged)
    <Progress value=100>                    ← existing progress bar (unchanged)
    <Tabs defaultValue="transcript">
      <TabsList>
        <TabsTrigger value="video">Video</TabsTrigger>
        <TabsTrigger value="transcript">Transcript</TabsTrigger>
        <TabsTrigger value="notes">Notes</TabsTrigger>
      </TabsList>
      <TabsContent value="video">
        [coming-soon message]
      </TabsContent>
      <TabsContent value="transcript">
        [transcript entry list OR empty-state message]
      </TabsContent>
      <TabsContent value="notes">
        [coming-soon message]
      </TabsContent>
    </Tabs>
  </CardContent>
</Card>
```

Default active tab: `transcript` (the only populated tab in this phase).

Card width: expand from existing `max-w-md` (28rem) to `max-w-2xl` (42rem) in the Done state to accommodate the transcript list. PENDING/PROCESSING/FAILED states keep `max-w-md`.

### Transcript Entry Rendering (D-07 — Claude's discretion, baseline applied)

Each `stitchedTranscript` entry renders as a single line:

```
[M:SS]  <transcript text>
```

- Timestamp (`[M:SS]` formatted from `sourceStartMs`): 14px / semibold / `text-foreground`
- Separator: single space (4px gap via inline)
- Text: 16px / regular / `text-foreground`
- Each entry is a `<div>` with `flex gap-2 items-baseline`
- Entry list: `<div className="flex flex-col gap-2">` — 8px between lines
- No border, no card wrapping per entry — plain list for readability

Timestamp format: `Math.floor(sourceStartMs / 60000)` minutes + `:` + zero-padded seconds (`String(Math.floor((sourceStartMs % 60000) / 1000)).padStart(2, '0')`). Example: `[1:04]`, `[12:30]`.

### Tab Interaction Behavior

- All three tabs (Video, Transcript, Notes) are **enabled and clickable** (D-06). No `disabled` prop on any TabsTrigger.
- Clicking Video or Notes tabs shows the coming-soon message inside that tab's content area.
- Default tab on render: `transcript`.
- No URL hash change on tab switch (keep routing simple; Phase 4/5 can revisit).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable — no new form submission in this phase |
| Transcript tab label | `Transcript` |
| Video tab label | `Video` |
| Notes tab label | `Notes` |
| Video tab coming-soon | `Video clips will be available here once processing is complete.` |
| Notes tab coming-soon | `Study notes will appear here in a future update.` |
| Empty transcript heading | *(none — inline message only, no separate heading)* |
| Empty transcript body | `No mentions of "[topic]" were found in this video.` — where `[topic]` is substituted with the job's actual topic value (D-08) |
| Error state (FAILED) | Unchanged from Phase 2: existing `errorMessage` from job record displayed inside `AlertDescription`. Heading: `Something went wrong`. Button: `Try again` |
| Destructive confirmation | Not applicable — no destructive actions in this phase |

Copy rules:
- Topic interpolation in the empty-state message uses the job `topic` field. Wrap in quotes: `"[topic]"`.
- Coming-soon messages use neutral, informative tone — no exclamation marks, no emoji.
- All copy uses sentence case.

Source: D-06, D-07, D-08 from `03-CONTEXT.md`. Coming-soon copy is Claude's discretion per D-06.

## State Matrix

| State | What the User Sees |
|-------|--------------------|
| PENDING / PROCESSING | Unchanged: progress bar + rotating messages (no tab container shown) |
| DONE — transcript has entries | Tab container (default: Transcript tab). Transcript list of `[M:SS] text` lines. Video and Notes tabs show coming-soon messages. |
| DONE — stitchedTranscript is empty | Tab container (default: Transcript tab). Empty-state message: `No mentions of "[topic]" were found in this video.` Video and Notes tabs show coming-soon messages. |
| FAILED | Unchanged: destructive Alert + `Try again` button (no tab container shown) |

## Accessibility

- Tab container uses shadcn `Tabs` (Radix UI) — keyboard navigation (arrow keys between triggers) and ARIA roles (`tablist`, `tab`, `tabpanel`) are provided by Radix primitives.
- Coming-soon messages inside inactive tabs are still in the DOM but hidden via Radix `TabsContent` visibility — accessible to screen readers when the tab is active.
- Transcript entry list: no interactive elements — plain read-only text. No additional ARIA roles needed.
- `aria-live="polite"` on the h1 wrapper in DONE state is already present in `status-view.tsx` — keep it; it announces "Done!" when the status transitions.
- Minimum tab trigger touch target: 44px height enforced via `min-h-[44px]` on `TabsTrigger` or via `TabsList` height.

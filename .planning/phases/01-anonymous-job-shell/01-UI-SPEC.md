## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(0 0% 3.9%)` — near-black | Page background, card background |
| Secondary (30%) | `hsl(0 0% 9%)` — dark grey | Input backgrounds, muted surfaces, nav areas |
| Accent (10%) | `hsl(0 0% 98%)` — near-white | Primary button fill, active progress bar fill |
| Destructive | `hsl(0 72.2% 50.6%)` — red | Failure/error state Alert background border, error icon |

**Color scheme: dark mode as the default** (source: Claude's Discretion — student-focused tool used in late-night study sessions; dark default reduces eye strain; aligns with shadcn "dark" preset defaults).

Accent reserved for:
1. Primary "Clip It" submit button fill
2. Progress bar filled portion (processing state)
3. "Try again" button fill on failure state

Accent is NOT used for: input borders, helper text, status message text, page background, card borders.

Muted text color (helper text, placeholders, rotating status messages): `hsl(0 0% 63.9%)` — shadcn default muted-foreground.

## Component States

### Submission Form

| State | Visual |
|-------|--------|
| Default | White-on-dark card, URL input empty, topic input empty, button enabled |
| Input focused | Input border highlights to accent ring (shadcn default focus ring) |
| Input validation error | Red border on invalid input, inline error message below field at 14px/400 |
| Submitting (pending) | Loading overlay covers form card; spinner icon + "Submitting…" label centered; button disabled |
| Submitted (success) | Loading overlay transitions to status view; submission form unmounts |

### Loading Overlay

| Property | Value |
|----------|--------|
| Coverage | Full form card area (not full page) |
| Background | `hsl(0 0% 3.9% / 0.85)` — semi-transparent dark over card |
| Content | Centered: spinning Loader2 icon (lucide, 24px) + "Submitting…" label at 16px/400 |
| Animation | Loader2 spins at 1 turn/s via `animate-spin` (Tailwind default) |

### Status View (processing)

| Property | Value |
|----------|--------|
| Progress bar | shadcn `Progress` component, accent fill, animates between 10% → 90% during PENDING/PROCESSING |
| Status message | Rotating text below progress bar, 16px/400, muted color, updates on Realtime status changes |
| Message cycle | Rotates every 4 seconds through the declared message list (see Copywriting Contract) |

### Status View (failed)

| Property | Value |
|----------|--------|
| Display | shadcn `Alert` with `variant="destructive"` |
| Contents | Error heading (16px/600) + plain-language error body (14px/400) + "Try again" Button below |
| Progress bar | Hidden on failed state |

## Interaction Contracts

### Form Submission Flow

1. User fills YouTube URL input → User fills topic input → clicks "Clip It" button
2. Button click triggers Server Action (`submitJob`)
3. Loading overlay appears immediately (optimistic UI via `useFormStatus` isPending)
4. On Server Action resolve with `{ jobId }`: client stores job ID in React state (never URL), triggers router transition to `/status`
5. On Server Action resolve with `{ error }`: overlay hides, inline validation errors display below relevant fields

### Status Page Load

1. Page server component calls `getUser()` → looks up active job for that `userId`
2. If no active job found: redirect to submission form
3. If job found: render status view shell; client component mounts and subscribes to Supabase Realtime
4. Progress bar starts at 10% immediately on mount (not 0% — avoids "dead" appearance)

### Realtime Status Transitions

| Job status | UI change |
|------------|-----------|
| PENDING | Progress bar at 10%, first status message |
| PROCESSING | Progress bar increments toward 90%, messages cycle |
| DONE | Progress bar animates to 100%, status message "Done!" — then result content appears (placeholder in Phase 1) |
| FAILED | Alert destructive variant appears with `errorMessage` from database; "Try again" button visible |

### "Try again" Button

- Triggers `router.push('/')` — returns user to submission form
- No confirmation dialog required (non-destructive navigation action)
- Label: "Try again" (sentence case, not "TRY AGAIN")

### Rotating Status Messages (source: Claude's Discretion — D-10)

Displayed in order, cycling every 4 seconds during PENDING/PROCESSING:

1. "Finding your topic in the video..."
2. "Reading through the transcript..."
3. "Pulling the right moments..."
4. "Building your clip plan..."
5. "Almost there..."

### Error State Copy

Each `errorMessage` from the database is surfaced verbatim in the Alert. The worker (Phase 2+) must write human-readable messages. Recommended message patterns (enforced when worker is implemented):

| Failure cause | Display text |
|---------------|--------------|
| No usable transcript | "This video doesn't have a usable transcript. Try a video with captions enabled." |
| Video not found / private | "This video isn't accessible. Check the URL and try again." |
| Topic not found in video | "No mentions of that topic were found in this video. Try a different topic or video." |
| Generic / unexpected | "Something went wrong on our end. Please try again in a moment." |

### Destructive Actions in Phase 1

None. Phase 1 contains no destructive actions (no delete, no cancel, no irreversible mutations surfaced to the user).

## Accessibility Contract

- All form inputs have associated `<Label>` components via `htmlFor` / `id` linkage (shadcn default)
- Error messages are associated with their input via `aria-describedby`
- Progress bar uses shadcn `Progress` which renders `role="progressbar"` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`
- Status heading uses `aria-live="polite"` region — rotating messages update inside a live region so screen readers announce changes
- Failure Alert uses `role="alert"` (shadcn Alert destructive variant default)
- Color contrast: near-white text (`hsl(0 0% 98%)`) on near-black background (`hsl(0 0% 3.9%)`) — contrast ratio > 18:1, exceeds WCAG AA (4.5:1)
- Minimum touch target: 44px height on all buttons and inputs (source: default — WCAG 2.5.5)

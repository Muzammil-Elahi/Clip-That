<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase Realtime → Browser client | Realtime pushes job row UPDATE events; client reads status and errorMessage from payload |
| Server component → Prisma query | Job lookup is gated by userId from getUser() — prevents cross-user job access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Supabase Realtime cross-user leakage | mitigate | RLS on Job table (enabled in Plan 01-01) with `auth.uid()::text = "userId"` policy; Realtime subscription filtered to `userId=eq.<uid>`; job table added to supabase_realtime publication (per RESEARCH Pattern 6 and Pitfall 4) |
| T-03-02 | Spoofing | Status page session validation | mitigate | `src/app/status/page.tsx` calls `getUser()` (network-validated) not `getSession()` (cookie-trusted) per RESEARCH Pitfall 6; redirect to / if no valid user |
| T-03-03 | Tampering | XSS via errorMessage display | mitigate | `errorMessage` from Realtime payload rendered as JSX text node inside `AlertDescription`; never uses `dangerouslySetInnerHTML`; React auto-escapes string content |
| T-03-04 | Information Disclosure | IDOR on job lookup | mitigate | `prisma.job.findFirst({ where: { userId: user.id, ... } })` scopes query to the authenticated user's own jobs; the job ID is never exposed in the URL (per D-07) |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan; all packages from Plan 01-01 and verified in Package Legitimacy Audit |
</threat_model>

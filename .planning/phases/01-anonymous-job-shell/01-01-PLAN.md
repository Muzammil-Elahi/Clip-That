<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Server Action | User-supplied form data crosses here; validated server-side with Zod before any DB write |
| Server Action → Supabase Auth | `getUser()` re-validates the JWT with the Supabase Auth server on each submission |
| Server → Supabase PostgreSQL (via Prisma) | Job INSERT gated by RLS: `userId` must equal `auth.uid()` |
| Worker → Supabase PostgreSQL | Worker uses service-role key (bypasses RLS); key must never appear in `NEXT_PUBLIC_*` env vars |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | `supabase.auth.getUser()` in Server Action | mitigate | Always call `getUser()` (network-validated), never `getSession()` (cookie-trusted) — see RESEARCH Pitfall 6 |
| T-01-02 | Tampering | `submitJob` Server Action form inputs | mitigate | Zod `submitJobSchema.safeParse()` validates `youtubeUrl` (URL + YouTube regex) and `topic` (min 2, max 200) before any DB write |
| T-01-03 | Information Disclosure | Job ID exposure | mitigate | `submitJob` returns `{ jobId }` held in React state only; job ID is never written to URL, localStorage, or sessionStorage (per D-07) |
| T-01-04 | Information Disclosure | Supabase Realtime — cross-user row leakage | mitigate | RLS on `Job` table with `auth.uid()::text = "userId"` policy; table added to `supabase_realtime` publication with RLS enforced (per RESEARCH Pitfall 4) |
| T-01-05 | Denial of Service | `signInAnonymously()` abuse creating infinite anonymous user records | accept | Supabase built-in IP rate limit (30/hr) provides baseline protection; Cloudflare Turnstile available as future mitigation if abuse occurs (per RESEARCH Pitfall 7) |
| T-01-06 | Elevation of Privilege | Supabase service-role key leak | mitigate | Service-role key used only in Railway worker (Phase 2+); never set as `NEXT_PUBLIC_*`; `.env.local` in `.gitignore` |
| T-01-07 | Tampering | CSRF on Server Action form submission | accept | Next.js Server Actions include built-in encrypted origin check for CSRF protection |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | All packages in RESEARCH.md Package Legitimacy Audit table verified as Approved; no [ASSUMED] or [SUS] packages in install list |
</threat_model>
